# Database

## 1. Conventions

Every table follows the same rules, which is what allows one generic CRUD/document engine to
serve the whole application.

| Concern | Convention |
| --- | --- |
| Primary key | `id` — UUID v4 (`UUID(as_uuid=False)`), generated by the model, never sequential |
| Tenant | `company_id` on every business table, enforced by the session-level filter (see architecture) |
| Audit | `created_at`, `updated_at` (naive UTC), `created_by`, `updated_by` |
| Soft delete | `is_deleted`, `deleted_at`, `deleted_by` where history matters; hard delete is not exposed by the API |
| Money | `Numeric(18, 4)`; unit prices `Numeric(18, 8)`; percentages and rates `Numeric(9, 4)` — never floats |
| Time | naive UTC in storage (`utcnow_naive()`), ISO-8601 in the API; clients localise |
| Document status | `status` string column backed by `app.core.enums.DocumentStatus` |
| Numbering | `document_no` unique per company + `NumberSequence`, allocated inside the transaction |
| Indexes | every FK, every `(company_id, status)`, every `(company_id, document_date)` and every unique business key |
| Constraints | unique business keys, `CHECK` constraints for non-negative quantities/amounts and for enum-like columns |

Names are singular snake_case for tables (`sales_orders`) and the model classes are singular
CamelCase (`SalesOrder`).

## 3. Invariants enforced by the database

* **Stock ledger is append-only.** `stock_ledger_entries` rows are never updated or deleted;
  a correction is a new row with `is_reversed`/`reversal_of_id`. `stock_balances` is a
  derived table rebuilt from the ledger inside the same transaction.
* **Units cannot be mixed silently.** Quantities are stored in the product's base unit;
  every line stores the transaction unit, the base unit and the conversion factor used, so
  history remains explainable when a factor changes.
* **Ledger entries balance.** `journal_entries.total_debit == total_credit` is checked before
  commit; posting a document twice raises `conflict` (unique link on `ledger_document_links`).
* **Posted documents cannot be mutated.** The document service refuses updates outside
  `draft`/`rejected`; unposting writes reversal entries and requires a reason.
* **Numbering is gap-free per sequence.** `number_sequences` rows are locked for update
  while the next value is taken, and the value is consumed inside the caller's transaction.
* **Foreign keys everywhere**, with `ondelete` chosen deliberately (`RESTRICT` for ledger
  and document references, `CASCADE` for pure child rows such as document lines).

## 4. Migrations

Alembic owns the schema; the initial revision creates all 195 tables.

```bash
cd backend
.venv/bin/python -m alembic upgrade head          # apply
.venv/bin/python -m alembic revision --autogenerate -m "add x"   # after model changes
.venv/bin/python -m alembic downgrade -1          # roll back one revision
```

Notes for authors:

* Autogenerate is a starting point: always review the diff, and replace
  `postgresql.JSONB(astext_type=Text())` with `sa.Text()` when the revision did not import
  `Text` (SQLite has no JSONB on the render path).
* SQLite runs (tests, local smoke) need `render_as_batch=True`, which is already configured
  in `alembic/env.py`.
* The Flutter image build, the API image and the migration step all run from the same
  revision, so deploying means applying migrations before starting the API container.

## 5. Performance notes

* Hot list queries are covered by `(company_id, status, document_date)` indexes; the API
  caps `page_size` at 200 and defaults to 25.
* Ledger reports aggregate from `stock_ledger_entries`/`journal_entry_lines` with
  `(company_id, product_id)` / `(company_id, account_id)` indexes.
* Dashboard endpoints aggregate with SQL (`func.sum`) instead of loading rows, and each
  dashboard can be served from `cash_flow_snapshots`-style summaries where available.
* Searches use prefix matching on indexed `code`/`sku`/`name` columns through the search
  service, which returns grouped hits instead of scanning every table on the client.
